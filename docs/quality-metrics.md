# Метрики качества ПО

## Дата: 2026-10-08
## Проект: «Старый Бердск» — веб-система управления арендой объектов парка отдыха
## Версия: v0.9 (после инспекции дня 11)

## Целевые значения

### Код
- Средняя длина функции: ≤ 50 строк
- Цикломатическая сложность: ≤ 10
- Дублирование: ≤ 5%
- Комментарии: 10–20%

### Тестирование
- Покрытие тестами: ≥ 70%
- Кол-во тестов: ≥ 10
- Плотность багов: ≤ 5 на 1000 строк

### Производительность
- Время загрузки: ≤ 2 с
- Размер бандла: ≤ 500 KB
- Ошибки в консоли: 0

### UX
- Адаптивность: 320px+
- Клики до бронирования: ≤ 4

## Выводы

### В норме
- Сервисный слой покрыт тестами на 92.8% (цель 70%).
- Тестов 40 при минимуме 10; все зелёные (`npm test`).
- Ответ сервера — десятки миллисекунд, статика — 52 KB из 500 KB.
- Дублирование устранено в день 11 (NC-02, NC-07).
- Адаптивность и путь бронирования соответствуют целям.

### Требует улучшения
- Покрытие всего проекта 25.9%: нет интеграционных тестов маршрутов
  через Supertest (запланировано ещё в отчёте дня 5) и тестов фронтенда.
- Комментарии 23% — чуть выше нормы 10–20%, но это JSDoc по стандарту.

### Рекомендации
1. Добавить интеграционные тесты маршрутов через Supertest — поднимет
   общее покрытие и закроет долг из `docs/integration-test-report.md`.
2. Добавить smoke-тест фронтенда (загрузка карты, создание брони).
3. При росте `styles.css` — минификация; пока не требуется (10 KB).
