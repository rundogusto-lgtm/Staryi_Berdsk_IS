# Руководство по установке
## «Старый Бердск» — веб-система управления арендой объектов парка отдыха

**Версия:** 1.1

---

## 1. Требования
- Браузер: Chrome / Firefox / Edge последних версий.
- Node.js: 22+ (разработка и запуск; проверено на Node 24).
- Git.
- Сборка C++ не требуется: `better-sqlite3@12` ставится готовым бинарником.

## 2. Установка

```bash
git clone https://github.com/rundogusto-lgtm/Staryi_Berdsk_IS.git
cd Staryi_Berdsk_IS
npm install
npm run seed
npm start
```

Сервер: `http://localhost:3000`. Порт меняется переменной `PORT`:

```bash
# Bash (Linux, macOS, Git Bash)
PORT=8080 npm start

# PowerShell (Windows)
$env:PORT=8080; npm start
```

## 3. Настройка

| Параметр | Где | Значение по умолчанию |
|----------|-----|----------------------|
| Порт | `process.env.PORT` | 3000 |
| База данных | `data/park.db` (SQLite) | создаётся при `migrate()` |
| Тестовые базы | `process.env.TEST_DB` | `tests/test.db` и `tests/api.test.db` |
| Справочник объектов | `data/objects.json` | 8 объектов, загружается `npm run seed` |
| Горизонт записи | `MAX_DAYS_AHEAD` в `bookingService.js` | 90 дней |
| Лимит часов | `MIN/MAX_BOOKING_HOURS` | 1–12 |

Константы фронтенда (`MIN/MAX_BOOKING_HOURS` в `src/public/api.js`)
синхронизированы с серверными — менять парой.

## 4. Развёртывание

Локальный сервер (`npm start`) отдаёт и API, и фронтенд — этого достаточно
для защиты практики.

Отдельный хостинг не настроен. Для внешнего размещения нужен сервер с
поддержкой Node.js, потому что приложение использует SQLite и не может
работать как статика:

| Платформа | Подходит | Примечание |
|-----------|----------|-----------|
| GitHub Pages | ❌ | Отдаёт только статические файлы, Node.js не запускается |
| Render | ✅ | Бесплатный тариф, засыпает после 15 минут простоя |
| Railway | ✅ | Платный после пробного периода |
| Glitch | ✅ | Бесплатный тариф с ограничениями |

Если нужна только демонстрация без сервера, фронтенд можно собрать в
статическую версию: все обращения к данным идут через один файл
`src/public/api.js`, достаточно заменить его транспорт.

## 5. Проверка и тесты

```bash
npm test                # 89 тестов (Vitest + Supertest)
npm run test:coverage   # отчёт о покрытии, открыть coverage/index.html
```

Ожидается: **89 passed**, покрытие серверной части **98,5 %** (цель — 70 %).

Тесты разбиты на три файла и используют отдельные базы, чтобы не мешать
рабочей:

| Файл | Тестов | База | Что проверяет |
|------|--------|------|---------------|
| `tests/booking.test.mjs` | 43 | `tests/test.db` | бизнес-логика: валидация, цена, слоты, статусы |
| `tests/api.test.mjs` | 34 | `tests/api.test.db` | REST API целиком через Supertest |
| `tests/exceptions.test.mjs` | 12 | — | нормализация ошибок, тексты уведомлений |

Ни один тест не обращается к `data/park.db` — рабочая база остаётся нетронутой.

## 6. Решение проблем

| Симптом | Причина и решение |
|---------|-------------------|
| `npm install` требует Visual Studio / node-gyp | Стоит старый `better-sqlite3@11`. Обновитесь до v12 (`npm install`), у него есть prebuilt под Node 24 |
| Порт 3000 уже занят — сервер не стартует | Кто-то использует порт. Запустите с другим: `$env:PORT=3100; npm start` (PowerShell) или `PORT=3100 npm start` (Bash). В адресной строке укажите новый порт |
| В браузере открывается чужой сайт | На порту 3000 работает другое приложение. См. предыдущую строку |
| «Нет связи с сервером» | Сервер не запущен — выполните `npm start` и обновите страницу |
| Пустая карта (0 объектов) | Не выполнен сид — запустите `npm run seed` |
| `npm test` меняет `data/park.db` | Такого больше нет: тесты работают в `tests/test.db` и `tests/api.test.db`. Если база изменилась — проверьте, что запускаете `npm test` из корня проекта, где лежит `vitest.config.js` |
| Ошибка 409 «Слот уже занят» | Дата и объект уже забронированы — выберите другой слот |
| Ошибка 400 «Такой даты не существует» | Дата вроде бы есть в календаре, но её нет: например, 30 февраля. Выберите реальную дату |
| `npm run test:coverage` пишет «MISSING DEPENDENCY» | Не установлен `@vitest/coverage-v8` — выполните `npm install` |
