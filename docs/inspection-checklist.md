# Чек-лист инспекции кода

## Дата: 2026-10-08
## Проект: «Старый Бердск» — веб-система управления арендой объектов парка отдыха
## Инспектор: __________

Стандарты: `docs/coding-standards.md`, `.editorconfig` (отступ 2 пробела, LF, UTF-8).

## 1. Именование
- [ ] Переменные и параметры в camelCase (`objectId`, `totalPrice`).
- [ ] Функции в camelCase (`calcPrice`, `isSlotAvailable`).
- [ ] Классы в PascalCase (`ValidationError`, `ConflictError`).
- [ ] Константы в UPPER_SNAKE_CASE (`MAX_BOOKING_HOURS`, `BOOKING_STATUS`).
- [ ] Файлы в kebab-case (по стандарту; факт — см. NC-08).
- [ ] Имена осмысленные (нет `a`, `b`, `tmp`, `data` без уточнения).

## 2. Структура кода
- [ ] Отступы 2 пробела, единообразно во всех файлах.
- [ ] Нет длинных строк (> 100 символов, лимит из coding-standards.md).
- [ ] Функции не длиннее 50 строк.
- [ ] Нет глубокой вложенности (> 3 уровней).
- [ ] Нет дублирования кода (один и тот же блок в 2+ местах).

## 3. Комментарии
- [ ] Есть JSDoc у всех публичных функций (`@param`, `@returns`, `@throws` где нужно).
- [ ] Сложные участки прокомментированы (календарь, транзакции, границы валидации).
- [ ] Нет закомментированного кода.
- [ ] Нет устаревших комментариев (JSDoc соответствует сигнатуре).

## 4. Константы и магические числа
- [ ] Нет «магических чисел» (3000, 12, 8, 4500 без имени).
- [ ] Нет «магических строк» (`'cancelled'`, `'completed'` вразброс).
- [ ] Все константы вынесены в начало файла или отдельный модуль.
- [ ] Используются именованные константы вместо литералов.

## 5. Обработка ошибок
- [ ] Есть try/catch в критических местах (сеть, БД, парсинг).
- [ ] Исключения типизированы (`ValidationError` 400, `NotFoundError` 404, `ConflictError` 409).
- [ ] Сообщения исключений понятны пользователю.
- [ ] Нет «голых» catch без обработки (каждый catch что-то делает или логирует).

## 6. Модульность
- [ ] Один модуль = одна ответственность (`routes` — только HTTP, `services` — бизнес-логика).
- [ ] Нет циклических зависимостей.
- [ ] Фронтенд ходит в сеть только через `src/public/api.js`.
- [ ] Импорты упорядочены, лишних импортов нет.

## 7. Git
- [ ] Осмысленные сообщения коммитов на русском.
- [ ] Один коммит — одна логическая задача.
- [ ] Нет мусорных файлов в репозитории (БД, логи, coverage — в `.gitignore`).
- [ ] Есть `.gitignore` и `.editorconfig`.
