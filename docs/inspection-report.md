## Найденные несоответствия

### NC-01: Магическая строка 'cancelled' в objectService
- Файл: `src/services/objectService.js`, строки 57–58
- Категория: Константы и магические числа
- Описание: в SQL-условии `status != 'cancelled'` статус захардкожен строкой,
  хотя в `bookingService.js` есть именованная константа `BOOKING_STATUS.CANCELLED`.
- Рекомендация: импортировать `BOOKING_STATUS` из `bookingService.js` и использовать
  его вместо литерала.
- Приоритет: средний
- Статус: исправлено

### NC-02: Дублирование loadObjects/objectName в admin.js и director.js
- Файлы: `src/public/admin.js` (строки 36–54), `src/public/director.js` (строки 15–33)
- Категория: Дублирование кода / модульность
- Описание: функции `loadObjects()` и `objectName()` полностью продублированы
  в двух модулях (загрузка справочника через `fetch('/api/objects')`, подпись
  «Объект #id» как fallback). Прямое нарушение «один модуль = одна задача»
  и запрета дублирования из `coding-standards.md`.
- Рекомендация: вынести обе функции в `src/public/api.js` (который по стандарту —
  единственное место сетевых обращений фронтенда) и импортировать оттуда.
- Приоритет: высокий
- Статус: исправлено

### NC-03: Дублирование пограничных значений бронирования во фронтенде
- Файлы: `src/public/booking.js` (строки 7–8: `MAX_HOURS = 12`, `MIN_HOURS = 1`),
  `src/public/app.js` (строка 74: `hours < 1 || hours > 12`), `src/public/index.html`
  (строки 76, 81, 86: `min="1" max="12"`, `min="1"`, `min="0"`)
- Категория: Константы и магические числа
- Описание: границы «1–12 часов» заданы литералами в трёх местах. Серверные
  `MIN_BOOKING_HOURS`/`MAX_BOOKING_HOURS` при их изменении не подтянут фронт —
  проверки разъедутся.
- Рекомендация: завести в `src/public/api.js` именованные константы
  `MIN_BOOKING_HOURS`/`MAX_BOOKING_HOURS` (синхронизированы с сервером) и
  использовать их в `booking.js` и `app.js`.
- Приоритет: средний
- Статус: исправлено

### NC-04: Магическое число 4500 в showToast

  по умолчанию — пример «магического числа» из задания.

- Приоритет: низкий

### NC-05: Магическое число 8 в fillTable
- Файл: `src/public/ui.js`, строка 114 (`cell.colSpan = 8`)
- Категория: Константы и магические числа
- Описание: ширина заглушки «нет данных» захардкожена под самую широкую
  таблицу (админка, 8 колонок). В дашборде директора таблица уже (5 колонок),
  заглушка там шире таблицы. При добавлении колонки число придётся искать
  по всему файлу.
- Рекомендация: передавать `colSpan` параметром `fillTable(tbody, rows, emptyText, colCount)`
  с разумным значением по умолчанию; вызовы указывают свою ширину.
- Приоритет: низкий
- Статус: исправлено

### NC-07: Дублирование парсинга ответа /api/objects
- Файлы: `src/public/admin.js` (строки 38–39), `src/public/director.js` (строки 17–18)
- Категория: Дублирование кода / модульность

- Приоритет: средний
- Статус: исправлено

### NC-08: buildShape без JSDoc для параметра busy
- Файл: `src/public/map.js`, строка 53 (`function buildShape(object)`)
- Категория: Комментарии
- Описание: JSDoc объявляет `@param {boolean} busy`, которого нет в сигнатуре —
  устаревший комментарий после рефакторинга. Проверка чек-листа «нет устаревших
  комментариев» не пройдена.
- Рекомендация: убрать `@param {boolean} busy` из JSDoc.
- Приоритет: низкий
- Статус: исправлено

### NC-09: Файлы в camelCase вместо kebab-case
- Файлы: `src/services/bookingService.js`, `src/services/objectService.js`,
  `src/middleware/asyncHandler.js`, `src/public/*.js`
- Категория: Именование
- Описание: стандарт требует kebab-case для файлов (`booking-service.js`,
  `async-handler.js`), фактически все файлы в camelCase. Переименование
  затронуло бы ~20 импортов в `src/`, `tests/` и `index.html` и разорвало бы
  историю git (`git log --follow` частично теряет переименования), поэтому
  принято решение зафиксировать фактическое соглашение в стандарте.
- Рекомендация: обновить `docs/coding-standards.md` — зафиксировать camelCase
  для JS-файлов как действующее соглашение проекта.
- Приоритет: низкий
- Статус: исправлено (стандарт приведён в соответствие коду)
