## Приоритеты

- **Критические** — приложение не должно падать и не должно создавать
  неверные данные: 1, 2, 3, 4, 5, 6, 14, 15.
- **Важные** — пользователь должен получить понятное объяснение вместо
  молчаливого отказа: 7, 8, 9.
- **Средние** — устраняют неудобство, но не блокируют работу: 10, 11, 12, 13.

## Стратегия обработки

| Стратегия | Где применяется | Пример |
|-----------|-----------------|--------|
| **Fail fast** | Валидация на входе, до записи в БД | `assertBookingInput` бросает исключение до `INSERT` |
| **Типизированное исключение** | Все бизнес-ошибки сервиса | `ConflictError` вместо возврата `{ ok: false }` |
| **Fallback** | Отсутствующие справочники на фронтенде | `objectService` вернул `null` → подпись «Объект #7» вместо падения |
| **Graceful degradation** | Загрузка списков | Не удалось получить названия объектов — таблица всё равно строится по ID |
| **Централизованная обработка** | Ошибки HTTP | `errorHandler` превращает любую ошибку в ответ с текстом |

## Классы исключений

Иерархия реализована в `src/exceptions.js` и используется **одновременно**
на сервере и в браузере.

```
Error
 └── ApiError            status по умолчанию 0
      ├── ValidationError   400 — неверные входные данные
      ├── NotFoundError     404 — объект или бронь не найдены
      └── ConflictError     409 — действие конфликтует с состоянием данных
```

| Класс | HTTP | Когда выбрасывается |
|-------|------|---------------------|
| `ValidationError` | 400 | Дата, часы, гости, машины, статус не прошли проверку |
| `NotFoundError` | 404 | `objectId` или `bookingId` не существует |
| `ConflictError` | 409 | Слот занят, завершённую бронь отменить нельзя |
| `ApiError` | 500 | Неизвестная ошибка или сеть недоступна |

## Обработка в точке вызова

Вызывающий код не пишет `try/catch` под каждую операцию: функция `guard()`
нормализует любой отказ в объект для показа пользователю.

```javascript
const result = await guard(() => createBooking(payload));

if (!result.ok) {
  showToast({ title: 'Бронь не создана', text: result.message.text, kind: result.message.kind });
  return;
}

showToast({ title: 'Бронь создана', kind: 'success' });
refreshAll();
```

`toUserMessage(error)` возвращает `{ title, text, kind }`:
- `ValidationError` → kind `warning`, «Проверьте заполненные поля…»;
- `ConflictError` → kind `warning`, «Выберите другой объект или дату»;
- `NotFoundError` → kind `warning`, «Обновите страницу…»;
- `ApiError` со статустом 0 → kind `error`, «Проверьте, запущен ли сервер»;
- что угодно другое → kind `error`, стек уходит в `console.error`.

Тексты сообщений содержат не только факт ошибки, но и порядок действий
пользователя по её устранению.

## Взаимодействие со state machine брони

```
                  ┌──────────────────────────────────────┐
                  ↓                                      │
  [создана] → [ожидает оплаты] → [оплачена] → [активна] → [завершена]
      │               │               │            │            │
      └───────────────┴───────────────┴────────────┴────────────┘
                    ошибка валидации → бронь не создаётся
```

Состояние «Ошибка» реализовано как **отсутствие записи**: невалидный вход
не доходит до `INSERT`, поэтому брони со статусом `error` в справочнике нет.
Пользователь получает сообщение и может исправить ввод. Такой подход выбран
вместо «записать и пометить», чтобы в базе не оставалось мусорных строк.

Единственное исключение — `ConflictError` при гонке двух вкладок: первая
транзакция выигрывает, вторая получает 409 и тоже не создаёт запись.

## Проверка обработки ошибок

| № | Ситуация | Обработано | Тест |
|---|----------|------------|------|
| 1 | Бронь занятого слота | ✅ | `expect(() => createBooking(valid)).toThrow(ConflictError)` |
| 2 | Некорректная дата | ✅ | `validateDate('2027-02-30')`, `validateDate('завтра')` |
| 3 | Часы вне диапазона | ✅ | `getPriceQuote(1, 13, date)` → `ValidationError` |
| 4 | Превышена вместимость | ✅ | `validateBookingInput({ guests: 9 })` |
| 5 | Машин больше мест | ✅ | `validateBookingInput({ cars: 4 })` |
| 6 | Объект не найден | ✅ | `calcPrice(999, 2, date)` → `NotFoundError` |
| 7 | Бронь не найдена | ✅ | `setStatus(4242, 'paid')` → `NotFoundError` |
| 8 | Неизвестный статус | ✅ | `setStatus(id, 'archived')` → `ValidationError` |
| 9 | Отмена завершённой | ✅ | `cancelBooking` после `completed` → `ConflictError` |
| 10 | Некорректный JSON | ✅ | ручная проверка через `Invoke-RestMethod` |
| 11 | Сервер не запущен | ✅ | ручная проверка: карта показывает toast об ошибке |
| 12 | Неизвестный маршрут | ✅ | `GET /api/nope` → 404 |

Все 12 ситуаций подтверждены тестами или ручной проверкой. Падений приложения
не зафиксировано.
