# Диаграмма деятельности (Activity Diagram)

**Дата:** 2026-10-09
**Проект:** «Старый Бердск»
**Версия диаграммы:** 1.1 — добавлены ветвления обработки ошибок

Три диаграммы: создание брони, смена статуса администратором, отмена брони.

## 1. Создание брони

```mermaid
flowchart TD
  Start([Клик по объекту]) --> S1[Слот свободен на дату?]
  S1 -->|Нет| W1[/Показать «Объект уже занят»/]
  W1 --> End1([Выйти])

  S1 -->|Да| Card[Открыть карточку объекта]
  Card --> In[Ввод: дата, часы, гости, машины]
  In --> Quote[Запросить стоимость у сервера]
  Quote --> Calc[Цена = цена за час × часы × сезон]

  In --> Submit{Нажата «Забронировать»?}
  Submit -->|Нет| Quote
  Submit -->|Да| V1{objectId указан?}
  V1 -->|Нет| Err1[/400 «Не указан objectId»/]
  V1 -->|Да| V2{Дата в формате YYYY-MM-DD?}
  V2 -->|Нет| Err2[/400 «Некорректная дата»/]
  V2 -->|Да| V3{Дата существует в календаре?}
  V3 -->|Нет| Err3[/400 «Такой даты не существует»/]
  V3 -->|Да| V4{Дата не в прошлом?}
  V4 -->|Да| Err4[/400 «Дата уже прошла»/]
  V4 -->|Нет| V5{Дата не дальше 90 дней?}
  V5 -->|Да| Err5[/400 «Дата слишком далеко»/]
  V5 -->|Нет| V6{Часы от 1 до 12?}
  V6 -->|Нет| Err6[/400 «Минимум 1 час»/]
  V6 -->|Да| V7{Гостей от 1 до вместимости?}
  V7 -->|Нет| Err7[/400 «Превышена вместимость»/]
  V7 -->|Да| V8{Машин от 0 до мест парковки?}
  V8 -->|Нет| Err8[/400 «Превышено количество мест на парковке»/]
  V8 -->|Да| Tx[[Начать транзакцию]]

  Tx --> V9{Слот всё ещё свободен?}
  V9 -->|Нет| Rollback[Откатить транзакцию]
  Rollback --> Err9[/409 «Слот уже занят»/]
  V9 -->|Да| Insert[[INSERT в bookings,<br/>статус = pending]]
  Insert --> Commit[[Зафиксировать транзакцию]]
  Commit --> Ok[/201 Бронь создана/]
  Ok --> Redraw[Перерисовать карту:<br/>объект красный]
  Redraw --> End2([Готово])

  Err1 --> End3([Вернуться к форме])
  Err2 --> End3
  Err3 --> End3
  Err4 --> End3
  Err5 --> End3
  Err6 --> End3
  Err7 --> End3
  Err8 --> End3
  Err9 --> End3
```

### Почему проверка слота внутри транзакции

Проверка занятости и вставка идут одним блоком. Без этого два быстрых клика
по кнопке могли бы создать две брони на один слот: обе проверки видели бы
свободный слот и обе записали бы строку. Транзакция в better-sqlite3
выполняется атомарно, поэтому выигрывает только один.

## 2. Смена статуса администратором

```mermaid
flowchart TD
  Start([Нажата кнопка в панели]) --> Id[Отправить PATCH status]
  Id --> V1{Статус известен?}
  V1 -->|Нет| E1[/400 «Некорректный статус»/]
  V1 -->|Да| V2{Бронь существует?}
  V2 -->|Нет| E2[/404 «Бронь не найдена»/]
  V2 -->|Да| Update[[UPDATE bookings SET status]]
  Update --> Ok[/200 Бронь обновлена/]
  Ok --> Refresh[Перерисовать таблицу]
  Refresh --> Map[Обновить карту]
  Map --> End([Готово])

  E1 --> End
  E2 --> End
```

Допустимые переходы заданы таблицей `TRANSITIONS` в `src/public/admin.js`.
Уже завершённую бронь нельзя ни подтвердить, ни активировать.

## 3. Отмена брони

```mermaid
flowchart TD
  Start([Нажата «Отмена»]) --> Id[Отправить DELETE]
  Id --> V1{Бронь существует?}
  V1 -->|Нет| E1[/404 «Бронь не найдена»/]
  V1 -->|Да| V2{Статус completed?}
  V2 -->|Да| E2[/409 «Завершённую бронь отменить нельзя»/]
  V2 -->|Нет| Update[[SET status = cancelled]]
  Update --> Free[Слот освобождён:<br/>объект снова зелёный]
  Free --> Ok[/200 Бронь отменена/]
  Ok --> End([Готово])

  E1 --> End
  E2 --> End
```

### Отмена не удаляет запись

Бронь помечается как отменённая, а не удаляется из базы. Причина — история
операций нужна директору для сверки выручки: физическое удаление строки
сотрло бы след операции. При этом отменённая бронь не занимает слот, потому
что подсчёт занятости исключает статус `cancelled`.

## Обработка ошибок на уровне сервера

```mermaid
flowchart TD
  Req[Входящий запрос] --> H[[asyncHandler]]
  H --> Handler[Обработчик маршрута]
  Handler --> Svc[Сервисный слой]
  Svc --> Throw[Выброс типизированной ошибки]
  Throw --> H
  H -->|отказ передан в next| EH[[errorHandler]]
  EH --> IsApi{ApiError?}
  IsApi -->|Да| Code[Ответ с status и текстом]
  IsApi -->|Нет| Synt{Синтаксис JSON?}
  Synt -->|Да| Code400[400 «Некорректный JSON»]
  Synt -->|Нет| Log[Вывод стека в консоль сервера]
  Log --> Code500[500 «Внутренняя ошибка сервера»]
  Code --> Resp[Клиент]
  Code400 --> Resp
  Code500 --> Resp
```

Наружу отдаётся только текст для пользователя. Стек исключения показывается
в консоли сервера, чтобы не раскрывать внутренности в ответе.
